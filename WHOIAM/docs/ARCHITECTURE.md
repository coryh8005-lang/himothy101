# WHOIAM — Architecture

## Overview

WHOIAM is an Expo (React Native, TypeScript) iOS-first app. The core loop — goals, vault,
check-ins, progress — is **local-first**: everything lives in on-device SQLite, no account
required. Backend (Supabase), chatbot (Claude API), and subscriptions (RevenueCat) arrive in
Phases 2–3 and never become required for the core loop.

## Layout

```
app.config.ts        # ALL native config; ios/ is gitignored and regenerated by prebuild
src/app/             # expo-router routes (Expo SDK 57 template convention — note: PLAN.md
                     #   sketches a root app/; the code lives in src/app instead)
  _layout.tsx        # theme provider + DB migration bootstrap (runs before any screen)
  index.tsx          # Today (home dashboard)
  vault.tsx          # vault rules (functional at M3)
  progress.tsx       # unified activity log
  settings.tsx       # schedules, vault management, about
src/components/      # design system (Screen, Card, ThemedText/View, app-tabs)
src/constants/       # theme tokens (colors light+dark, spacing, radii, fonts)
src/db/              # Drizzle schema + generated SQL migrations + client
src/hooks/           # useTheme, useColorScheme
scripts/verify-db.mjs# runs generated migrations against real SQLite (better-sqlite3)
docs/                # this file, VAULT_FLOW.md, APPLE_SETUP.md
```

Future homes (created in the milestone that needs them): `src/vault/` (isolates
react-native-device-activity behind one module), `src/notifications/`, `src/features/`
(pure logic: goals, checkins, slipups, streaks).

## Data

- **SQLite via expo-sqlite + Drizzle ORM.** Schema in `src/db/schema.ts`; migrations are
  generated (`npm run db:generate`), imported as `.sql` strings (babel inline-import +
  metro `sql` sourceExt), and applied on app launch by `useMigrations` in `_layout.tsx`.
- Timestamps are unix-epoch **milliseconds**; local calendar days are `YYYY-MM-DD` strings.
- **Opaque Screen Time tokens never enter SQLite.** App/extension-shared state (selection
  tokens, shield config, extension event history) lives in App Group UserDefaults — the only
  storage iOS extensions can share. `vault_rules.selection_ref` is a pointer into it; a
  foreground sync bridges extension history into `unlock_events` (M4).
- Tables: `goals`, `vault_rules`, `unlock_events`, `check_ins`, `slip_ups`, `streaks`
  (denormalized, recomputable), `notification_schedules`, `kv`.

## UI

Design tokens in `src/constants/theme.ts`: warm neutrals, deep sage-teal tint, dark mode
first-class (`userInterfaceStyle: automatic`). Screens compose `Screen` + `Card` +
`ThemedText`. Tabs are native (`expo-router/unstable-native-tabs`) with SF Symbol icons on
iOS; `app-tabs.web.tsx` provides the web fallback used in development.

## Verification commands

| Command | What it proves |
|---|---|
| `npm run typecheck` | TS strict mode clean |
| `npm run verify:db` | generated migrations run on real SQLite; tables, joins, FKs verified |
| `npx expo export --platform ios` | full Metro/Hermes bundle compiles |
| `npx expo start` → iOS Simulator | app boots, tabs render, DB migrates on launch |
